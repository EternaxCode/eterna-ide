# 작업 지식을 재사용하는 AI IDE — 연구 기반 설계 초안

작성: 2026-10-18 KST. 상태: 검토용 설계, 구현 및 성능 검증 전.

## 목표

여러 프로젝트의 코드, 작업, 결정과 검증 결과를 연결하고, 다음 작업에 유효한 근거를 찾아 실제 수정·테스트까지 이어가는 개인용 로컬 IDE를 만든다. 기록을 많이 쌓는 것보다 필요한 근거를 찾고 과거의 잘못된 결론을 반복하지 않는 것이 성공 기준이다.

## 제품 형태 비교

1. 독립 로컬 앱 + 교체 가능한 실행 어댑터: 추천. 여러 프로젝트를 묶는 지식 화면과 작업 흐름을 자유롭게 구성한다. 편집·터미널·프로세스 관리 구현 부담은 있다.
2. VS Code 확장: 기존 편집·디버깅을 활용해 빨리 배포할 수 있으나 앱 전체의 탐색 흐름은 호스트 제약을 받는다.
3. IDE 전체 포크: 제어 범위가 넓지만 업스트림 병합과 확장 호환성 유지 비용이 커 초기에는 보류한다.

## 핵심 구조

사용자 목표 → 완료 조건 → 현재 저장소 확인 → 필요한 근거 선택 → 변경 생성 → 실행 검증 → 검토 → 경험 기록.

- UI: 프로젝트/작업 목록, 코드·diff·미리보기, 근거 패널, 테스트·실행 기록. 그래프는 전체 탐색과 작업 부분 그래프를 전환한다.
- Context service: 정확한 이름은 문자열·심볼 검색, 개념은 의미 검색, 영향 범위는 의존 관계 탐색을 사용한다. 순위 점수는 모델의 attention 값으로 표시하지 않는다.
- Knowledge service: 결정·경험·제약의 상태와 원본 근거를 관리한다. 프로젝트 간 추천은 적용 조건과 차이를 함께 반환한다.
- Run controller: 단계·예산·취소·도구 권한·재시도를 관리한다. 기본은 한 실행 주체이며 독립적으로 나눌 수 있는 작업만 선택적으로 병렬화한다.
- Execution adapter: 저장소 읽기, patch, 테스트, 미리보기 기능을 제공한다. 모델 연결과 프로세스 실행을 분리한다.
- Evidence store: 실행 사건을 순서대로 추가 저장한다. 실패 후 새 세션은 현재 파일과 미완료 단계부터 대조한다.

## 서로 다른 세 그래프

1. 코드 관계: 파일, 심볼, import, 호출, 테스트 연결. 파서로 확인한 관계와 동적 호출 추정은 구분한다.
2. 지식 관계: 결정, 근거, 교훈, 제약, 반례, 대체 관계. AI가 제안한 연결은 후보 상태다.
3. 실행 관계: 목표, 변경안, 실행 명령, 테스트 결과, 산출물. 어떤 코드 상태에서 무엇을 확인했는지 연결한다.

같은 식별자 체계로 연결하지만 데이터의 의미와 신뢰 수준을 섞지 않는다.

## 기록과 유효성

KnowledgeRecord: id, projectId, kind, content, sourceRefs, scope, status, createdAt, observedAt, validAtRevision, contentHashes, supersedesId.

RunEvent: id, runId, sequence, kind, inputRef, outputRef, baseRevision, workingTreeDigest, environmentRef, timestamp, outcome.

- 지식 상태는 candidate / verified / stale / superseded / rejected. 검증 방식과 적용 범위를 함께 표시한다.
- 커밋 SHA뿐 아니라 미커밋 변경의 해시를 포함한다. 테스트 근거에는 명령·종료 코드·환경·로그를 연결한다.
- 파일·의존성·설정이 바뀌면 관련 근거를 재검증 대상으로 표시한다. 영향 범위가 불명확하면 유효하다고 추정하지 않는다.
- 요약은 원문을 대체하지 않고 원문 참조를 유지한다. 오래된 기록은 삭제하지 않고 상태를 바꾼다.
- 외부 문서와 코드 주석은 자료로 취급하며 실행 권한이나 상위 지침으로 승격시키지 않는다.

## 맥락 구성 절차

1. 사용자 목표, 적용되는 명시적 지침, 완료 조건을 고정한다.
2. 저장소·브랜치·미커밋 상태와 현재 오류를 읽는다.
3. 작업 종류에 맞는 검색을 하고 근거 후보를 합친다.
4. 오래된 증거, 중복, 다른 프로젝트에만 적용되는 규칙을 걸러낸다.
5. 토큰 예산 내 근거 묶음과 원문 참조를 만든다. 근거가 부족하면 추가 탐색하거나 부족함을 보고한다.
6. 새 오류·수정·테스트 결과가 생기면 필요한 부분만 갱신한다.

정책과 필수 제약은 검색 순위가 낮다는 이유로 누락하지 않는다. 관련성과 진실성은 다른 속성이다.

## 실행과 실패 처리

- 읽기/조언, 변경안 생성, 격리된 수정·테스트 세 모드를 제공한다. 배포 같은 외부 변경은 별도 권한으로 다룬다.
- Git worktree는 변경 격리이며 보안 sandbox가 아니다. 임의 코드 실행의 자격 증명·네트워크·파일 접근 제한은 실행기에서 별도로 적용한다.
- 중단 버튼과 실행별 시간·토큰·비용 상한을 둔다. 같은 실패가 반복되면 자동 반복을 중지하고 관찰된 원인과 미완료 작업을 남긴다.
- AI의 자기평가는 참고 자료다. 실제 테스트 종료 결과와 사용자 흐름 검증이 완료 판정의 근거다.
- 테스트 인프라 오류와 제품 코드 실패를 분리한다. 기존 테스트를 약화해 통과한 변경도 검토 대상이다.
- 재시작 시 read/test는 정책에 따라 재시도할 수 있지만 결과가 불명확한 외부 쓰기는 상태 확인 없이 반복하지 않는다.

## 저장 및 기술 경계 제안

초기에는 TypeScript 기반 로컬 UI와 로컬 서비스, SQLite의 레코드/관계/전문 검색, Markdown 내보내기를 제안한다. 전용 그래프 서버는 측정 결과가 필요할 때 추가한다. 편집기·그래프 렌더러·모델 SDK의 제품 선택과 버전은 구현 시작 시 호환성을 검증한다.

로컬 저장과 로컬 모델 추론은 다르다. 외부 모델을 선택하면 전송되는 파일 범위와 근거 묶음을 보여준다. 비밀 파일은 기본 인덱싱 제외, 자격 증명은 지식 DB와 실행 로그 밖에 보관한다. 이 설계는 특정 공급사나 새 모델 학습에 의존하지 않는다.

## 첫 버전 범위

- 사용자가 선택한 실제 저장소 등록과 변경 감지.
- 작업별 근거 검색, 부분 그래프, 원본 파일 열기.
- GPT·Claude 공통 지식 인터페이스와 공급사별 실행 어댑터. 구독 로그인 지원 범위는 아래 인증 설계를 따른다.
- 격리된 실행 공간에서 테스트, 취소, 예산 상한, 실행 기록.
- 작업 종료 시 결정·실패·교훈 후보 생성과 채택.
- 다음 세션에서 기록 복원 및 변경된 근거의 stale 처리.
- 다른 프로젝트에서 참고할 기록을 출처와 적용 조건을 포함해 제안.

모델 학습, 무제한 에이전트 조직, 자동 배포, 전체 조직 협업은 첫 버전 범위 밖이다.

## 검증 설계

실제 프로젝트 2개에서 총 12개 작업을 선정하는 파일럿을 제안한다. 버그 수정·변경 영향 탐색·과거 결정 조회·중단 복구를 포함하고 각 작업은 고정된 시작 상태와 독립적인 완료 조건을 가진다.

같은 모델·도구·예산으로 A(일반 검색), B(혼합 검색), C(B+지식 관계), D(C+유효성 검사)를 비교한다. 순서를 섞고 각 조건을 3회 반복하며 평가 작업의 정답·미래 커밋을 기억에 유출하지 않는다. 해당 작업을 수행하는 데 정당하게 이용 가능한 과거 기록만 제공한다.

측정: 실제 해결률, 필요한 파일 검색 재현율, 오래된 근거 사용률, 사람의 검토 시간, 입력/출력 토큰, 비용, 총 소요 시간. 개별 실패도 함께 보고한다. 작은 파일럿으로 일반적인 우수성을 주장하지 않는다.

기능 수락 조건: 재시작 후 데이터 복원, 원문 링크 추적, 코드 변경 후 과거 테스트 근거 재검증 표시, 다른 프로젝트 지식의 범위 표시, 실행 중단과 상한 작동, 원본 작업의 미커밋 변경 보존. 이 조건과 실제 작업 평가를 통과하기 전에는 연구상의 성능 개선을 제품의 성능으로 홍보하지 않는다.

## 설계 결론

카파시의 attention 설명은 개념적 출발점으로 유지한다. 제품의 중심은 현재 작업에 맞는 근거 선택, 코드 변화에 맞춘 기억 갱신, 검증 가능한 실행, 다시 이어갈 수 있는 기록이다. 최신 방법은 교체 가능한 기능으로 도입하고 실제 평가에서 도움이 되는 것만 기본값으로 남긴다.

## 추가 요구: GPT·Claude 공통 지식과 구독 계정 관리

사용자 확인: API 키 여러 개가 아니라 ChatGPT·Claude 구독 계정 로그인을 원한다. 이를 API 과금으로 조용히 대체하지 않는다. 아래는 설계이며 실제 로그인과 모델 호출은 아직 검증하지 않았다.

### 모델과 계정에서 독립된 지식

- Knowledge service와 Evidence store는 IDE 소유다. GPT와 Claude는 동일한 검색·조회·기록 제안 인터페이스를 사용한다. 모델 가중치나 내부 추론 상태를 공유하는 기능이 아니다.
- 공통 ContextBundle은 목표, 완료 조건, 적용 지침, 지식 버전, 코드 상태, 관련 원문, 완료/미완료 단계, 실행 결과, 다음 행동을 담는다.
- GPT에서 Claude로 전환할 때 공급사 고유 세션 ID를 넘기지 않고 이 묶음으로 새 실행을 구성한다. 제공 가능한 도구와 입력 한도를 어댑터가 확인한다. 동일 정보 접근은 동일 판단이나 답변을 보장하지 않는다.
- 공유 기록에는 작성 모델·실행·근거를 남긴다. 모델끼리 서로 동의했다는 이유만으로 verified로 승격하지 않는다. 상충하는 의견은 함께 보관한다.
- 쓰기는 버전 검사와 트랜잭션을 거친다. 중복 기록과 동시 수정 충돌을 탐지한다. 모델 교체 전 진행 중 도구 실행이 끝났는지 확인해 중복 patch/명령 실행을 방지한다.
- 개인·업무 계정별로 접근 가능한 프로젝트와 외부 전송 대상을 명시한다. 공유 대상으로 허용한 지식만 다른 계정·공급사에 전달한다.
- 로컬 API를 기본 인터페이스로 하고, 공식 도구에서 접근하도록 MCP 연결을 추가할 수 있다. 비밀 값은 두 인터페이스 모두 반환하지 않는다.

### 공식 인증 경로와 제약

2026-10-18 확인한 [OpenAI Codex app-server 문서](https://developers.openai.com/siwc/token-sharing-open-source/codex-app-server)는 ChatGPT 플랜 사용이 허가된 OAuth 토큰으로 앱을 연결하는 방식을 설명한다. 앱 등록·권한·대상 플랜 등 해당 연동의 전제 조건을 구현 시 확인하고, 실제 완료된 호출로 접근 가능 여부를 검증한다. 모델 목록 조회만으로 권한을 확정하지 않는다.

[Anthropic 공식 로그인 안내](https://support.claude.com/en/articles/13189465-log-in-to-your-claude-account)는 구독을 공식 앱과 Claude Code 사용 중심으로 설명한다. 일부 서드파티 사용은 Anthropic 재량으로 usage credits를 요구할 수 있으며, 타인을 위한 제품은 API 인증을 사용하도록 안내한다. 따라서 우리 IDE에서 Claude 구독 토큰을 직접 사용하고 기본 구독 한도로 차감되는 통합은 현재 확인되지 않은 요구다. Claude Code를 실행한다는 사실만으로 모든 래퍼의 구독 사용이 허용된다고 가정하지 않는다.

우선 Claude의 공식 도구가 공통 지식에 접근하는 연결과 작업 인계 경로를 설계한다. IDE 내부 구독 실행은 공식 지원 조건이 확인된 어댑터에만 활성화한다. 지원되지 않는 경우 상태와 이유를 표시하며 API나 usage credits로 자동 전환하지 않는다.

### 계정 프로필과 rotation

AccountProfile: id, provider, displayName, authMode, credentialRef, workspaceId, capabilities, permittedProjects, usageObservation, resetAt, observedAt, status.

- 인증 비밀은 macOS Keychain 또는 공식 인증 저장소에 보관하고 DB에는 참조만 둔다. 로그·그래프·프롬프트·내보내기에 토큰을 포함하지 않는다.
- 액세스 토큰 만료에 따른 갱신(refresh)과 다른 구독 계정 선택(rotation)을 분리한다. 공식 갱신 흐름을 사용하고 프로필별 동시 갱신을 직렬화한다.
- 여러 프로필 등록, 활성 프로필 표시, 프로젝트별 기본 계정, 연결 해제·재로그인을 제공한다. 공급사별 공식 지원 방식에 따라 저장 및 전환 범위가 달라질 수 있다.
- 자동 계정 선택 정책은 어댑터가 다중 계정 사용을 공식 지원하고 해당 계정/조직 정책이 허용하는 경우에만 활성화한다. 사용 한도를 우회하기 위한 무조건적인 순환은 기본 기능으로 확정하지 않는다.
- 전환은 작업/턴 경계에서 체크포인트를 저장한 뒤 수행한다. 실행 중인 외부 쓰기의 결과가 불명확하면 확인 없이 재실행하지 않는다.
- 사용 가능량은 공식 도구가 제공하는 관측값과 시각을 표시한다. 제공되지 않는 잔여량은 unknown이며 토큰 수로 구독 잔여량을 추정하지 않는다.
- rate limit은 재시도 가능 시각까지 대기, 인증 만료는 공식 refresh 후 필요 시 재로그인, 권한 거절은 해당 기능 중지로 분류한다. 일시 장애만 제한된 재시도 대상으로 삼는다.
- 적격 프로필이 없거나 한도에 도달하면 작업을 저장하고 대기한다. 유료 크레딧/API 사용은 별도로 사용자가 설정한 경우에만 가능하다.

### 추가 수락 조건

1. GPT가 남긴 결정·원문·테스트 결과를 Claude가 같은 버전으로 조회하고 반대 방향도 성립한다.
2. 모델/계정 변경 후 목표·지침·미완료 단계가 보존되고 도구 실행이 중복되지 않는다.
3. 개인/업무 프로젝트 권한 경계가 계정 전환 후에도 유지된다.
4. 인증 만료, 한도 소진, 제공사 장애, 취소를 각각 재현해 대기·복구 상태를 확인한다.
5. 지식 DB·로그·내보내기에 인증 비밀이 포함되지 않는다.
6. 실제 구독 연결 및 과금 경로를 확인하기 전에는 구독 통합·자동 rotation 완료로 표시하지 않는다.
