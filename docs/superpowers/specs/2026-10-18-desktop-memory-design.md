# Eterna Desktop — 지속되는 작업 기억과 관측 가능한 AI 실행

2026-10-18 · 검토용 설계 · 데스크톱 구현/벤치마크 전

## 제품 목표

Windows와 macOS에 설치해서 매일 개발·문서·조사 작업을 수행하는 개인용 앱. 사용자는 한국어 화면에서 목표·근거·변경·결과를 이해하고, 모델은 같은 구조화 지식을 이어받는다. 기본 기능에 브라우저 실행이나 별도의 Node 설치를 요구하지 않는 것이 목표다.

현재 Eterna 0.2.1의 데이터·작업 기록·공식 인증 경계는 보존한다. 모든 기능을 한 번에 교체하지 않고 실행 가능한 단계별 버전으로 전환한다. 이 문서는 목표 설계이며 아직 .app/.dmg/.exe를 생성했다는 뜻이 아니다.

## 현재 코드에서 확인한 문제

- Node/Express/localhost와 WebSocket에 UI가 직접 결합되어 있다.
- node-pty 세션 종료는 POSIX 프로세스 그룹을 사용하므로 Windows에서 그대로 작동하지 않는다.
- 작업 사본의 파일 본문과 workspace.baseline JSON에 같은 파일 내용이 저장된다.
- ContextBundle에 파일/지식 원문을 복사하고, 직렬화한 prompt에도 다시 넣어 중복이 생긴다.
- 매 작업마다 소스 사본 전체를 생성한다. 작은 프로젝트는 문제가 작지만 장기 운영의 증가 비용이 크다.
- Claude 터미널 화면은 구조화 실행 이벤트가 아니므로 화면 텍스트만으로 정확한 도구 호출을 추정할 수 없다.
- 현재 DB는 작은 실제 사용 데이터에 불과하다. 현재 디스크 크기로 장기 성능을 일반화하지 않는다.

관찰한 로컬 개발 환경: node_modules 약 532MB, dist 약 1.2MB, .data 약 780KB. node_modules는 개발 의존성/플랫폼 패키지를 포함하므로 데스크톱 설치 크기가 아니다. 이 수치를 Tauri의 절감률로 홍보하지 않는다.

## 기술 선택

| 접근 | 장점 | 비용/위험 | 결정 |
|---|---|---|---|
| Tauri 2 + Rust 코어 + 현재 React UI | OS WebView 사용, 네이티브 파일/프로세스/DB 관리, Node 서버 제거 가능 | 백엔드 재구현, WebView 차이, Windows PTY 검증 필요 | 추천 |
| Electron + 기존 Node 서비스 | 현재 기능을 빠르게 데스크톱으로 옮길 수 있고 렌더러가 일관됨 | Chromium/Node 배포 크기, 네이티브 모듈 ABI 관리 | 전환 속도가 최우선일 때 대안 |
| SwiftUI와 WinUI 별도 구현 | 각 OS에 깊게 맞출 수 있음 | UI·기능 두 벌 유지, 공유 코드 감소 | 첫 버전에서 제외 |

Tauri가 모든 경우에 더 적은 RAM이나 더 높은 FPS를 보장하지는 않는다. 설치 크기·전체 프로세스 메모리·배터리·터미널 안정성으로 검증한다. 화면은 WebView로 렌더링하지만 사용자는 브라우저 없이 설치된 독립 앱을 사용한다. localhost 웹사이트를 앱 창에 띄우는 방식 대신 IPC 명령/이벤트를 사용한다.

## 프로세스와 인터페이스

- Desktop shell: 창, 네이티브 폴더 선택, 메뉴, 알림, 키보드 단축키, 단일 인스턴스, 종료/복구.
- Rust core: 파일 접근, DB 트랜잭션, 검색, 사본 생성, 작업 스케줄, 권한, 실행 로그.
- Provider adapters: 공식 Codex/Claude 도구의 인증과 실행 수명주기를 연결. 계정 비밀을 지식 저장소에 저장하지 않는다.
- Render worker: 그래프 배치와 집계. UI 스레드에서 전체 그래프 레이아웃 계산을 하지 않는다.
- UI: 현재 에디터/변경 검토를 재사용하고 브라우저 fetch를 transport 인터페이스 뒤로 이동한다. 데스크톱은 IPC, 기존 웹판은 HTTP를 사용한다.

서버를 영구적으로 동봉하는 Node sidecar는 최종 구조에서 제외한다. 마이그레이션 중 필요한 개발용 호환 어댑터는 공개 데스크톱 완성본과 구분한다. 데이터 읽기·검색은 병렬화하고 DB 쓰기는 단일 작성자 큐에서 직렬화한다. 취소는 모델 요청·검색·PTY·렌더링에 각각 전달한다.

## 저장 구조: 본문 한 번, 관계와 사건은 참조

내부 데이터는 한국어나 영어 문장 파일의 모음이 아닌 타입이 있는 레코드와 해시 참조로 관리한다. AI도 바이너리 DB를 직접 이해하는 것이 아니다. 코어가 정확한 범위의 자료를 도구 응답으로 변환해 모델에 전달한다.

- objects: 콘텐츠 해시, 압축 방식/버전, 원본 길이, 검증 체크섬, 본문 위치.
- entities: 프로젝트/파일 버전/심볼/결정/교훈/제약/오류/테스트 결과. 안정된 ID와 유효 범위.
- relations: source, target, relation type, 출처, 관측/검증 상태, 유효 기간.
- events: 단조 증가 순번, 실행 ID, 사건 종류, 입력/출력 object 참조, 시각, 결과 코드.
- context_manifests: 목표·지침·선택한 파일 버전/근거 ID·토큰 예산·제공사. 전체 본문 복사를 피한다.
- workspaces: 시작 manifest, 변경 overlay, 승인·적용 기록. 기준 파일 내용은 object 참조.
- projections: 화면 목록·상태·검색을 위한 재생성 가능한 읽기 모델.

SQLite에 타입·관계·인덱스를 저장하고 큰 원문은 내용 주소 기반 객체 저장소에 한 번 보관한다. 작은 본문은 크기 기준으로 inline 저장할 수 있으나 동일 객체에는 동일 정책을 적용한다. 본문과 메타데이터를 모호하게 이중 원본으로 두지 않는다.

첫 구현은 파일/문서 단위 중복 제거를 사용한다. 작은 변경에도 큰 파일 전체가 달라지는 문제는 이후 실측 후 chunk/delta 방식으로 확장한다. 처음부터 복잡한 가변 청크나 벡터 전용 DB를 도입하지 않는다.

## 압축·무결성·정리

- 이미 압축된 이미지/바이너리와 짧은 본문은 재압축하지 않는다. 텍스트는 저비용 Zstandard 후보를 압축 시간과 절약량으로 평가한다.
- 내용 해시는 압축 전 바이트 기준으로 계산한다. 파일 원본은 Unicode 정규화·번역·개행 변환 없이 보존한다.
- 이벤트는 전체 상태를 매번 저장하지 않고 변경 사건을 기록한다. UI는 사건 묶음과 필요한 projection만 수신한다.
- 객체 파일을 임시 위치에 기록·검증·원자적 이동한 뒤 DB 참조를 커밋한다. DB 실패로 남은 미참조 객체는 다음 정리에 회수한다. 커밋된 참조가 없는 객체를 현재 유효 데이터로 취급하지 않는다.
- 자동 삭제 대상은 재생성 가능한 인덱스/캐시부터다. 사용자의 결정·원문·승인·미적용 변경은 AI 판단만으로 지우지 않는다.
- GC는 활성 실행, 보관된 manifest, 백업, 미적용 변경을 루트로 한 도달 가능성 검사와 유예 기간을 사용한다. 참조 수만 믿고 삭제하지 않는다.
- VACUUM/압축/인덱스 재생성은 실행 중인 편집을 막지 않도록 유휴 시간·예산 내에서 수행한다.
- 보관과 검색 인덱스는 분리한다. 임베딩은 원문 해시+임베딩 모델 버전별 캐시로 두고 재생성 가능하게 한다.

저장량의 1차 모델: 기존 반복 저장은 대략 실행 횟수×스냅샷 본문에 비례한다. 새 설계는 고유한 콘텐츠 버전+실행별 참조+활성 사본에 비례하도록 한다. 실제 절감률은 변경량과 보관 정책에 따라 달라지며 아직 측정하지 않았다.

## 작업 사본과 원본 보호

외부 공식 CLI는 일반 파일 시스템이 필요하므로 객체 DB만으로 실행할 수 없다. 실행할 때만 manifest를 작업 디렉터리로 materialize한다.

- 초기 동시 활성 사본 예산을 두고, 종료된 사본은 복원 가능성을 검증한 후 보관 상태로 전환한다.
- APFS 같은 copy-on-write 복사가 제공되면 사용하고, 다른 파일 시스템에서는 안전한 복사를 사용한다.
- 가변 작업 사본과 객체 원본을 hardlink로 공유하지 않는다. CLI의 파일 쓰기가 객체 원본을 변조하면 안 된다.
- 사용자가 편집 중인 파일은 시작 시 바이트/메타데이터를 고정한 snapshot으로 읽는다. 파일 감시 누락·동시 변경은 해시 재검사로 보완한다.
- 변경 적용은 원본 기준 버전과 검토한 결과 버전을 모두 확인한다. 충돌은 비교 화면으로 보낸다.
- dependencies를 무조건 생략한 현재 사본 정책은 개선한다. 개발 도구가 필요로 하는 의존성은 별도 재생성/재사용 정책으로 관리하고 자격 증명·비밀 파일은 명시적 범위로 처리한다.

## AI에 적합한 지식 운영

AI의 역할은 분류·요약·연결 제안·중복 후보 탐지·모순 발견이다. 저장소 코어는 스키마·권한·출처·버전·트랜잭션을 강제한다. 모델이 임의 SQL/스키마 변경/GC를 직접 수행하지 않는다.

주요 도구 계약: search_context, read_objects, trace_evidence, propose_memory, commit_validated_memory, inspect_run. 스코프와 바이트/토큰 예산이 필수다. 문서 안의 지시가 DB 권한을 바꿀 수 없다.

- 후보 지식과 검증된 지식을 분리하고, AI의 합의를 독립 검증으로 간주하지 않는다.
- 기억은 사건, 적용 조건이 있는 교훈, 원본 사실을 구분한다.
- 메모리의 무효화는 공유 취소·파일 변경·결정 대체를 여러 단계의 인계에도 전파한다.
- 긴 인계 체인의 검증 비용을 줄이기 위해 원본 근거의 의존 집합을 manifest에 집계한다. 원본 이벤트 연결은 유지한다.
- “모른다/찾지 못했다/오래됐다”는 정상적인 반환 상태다.

## 한국어와 언어 효율

UI, 작업 설명, 기본 요약, 오류 안내는 한국어다. 파일 경로·심볼·오류 코드·원문 인용은 정확한 원형을 유지한다.

한국어가 영어보다 항상 적은 토큰을 쓴다고 가정하지 않는다. 저장 크기, 모델 토큰 비용, 추론 품질은 다른 지표다. 한국어 원문을 보존하고 짧은 구조화 출력으로 중복을 줄이는 것을 기본으로 한다. 영어 중간 요약은 실제 모델별 평가에서 품질을 유지하며 이득이 확인되는 경우에만 선택한다. 언어를 바꾸어 생기는 모호성/번역 손실도 측정한다.

검색은 코드 식별자 exact/prefix, 한국어 텍스트 검색, 관계 탐색을 조합한다. FTS5 unicode61만으로 한국어 형태소 검색이 완성된다고 보지 않는다. 띄어쓰기 변형과 두 글자 검색어를 포함한 fixture로 토크나이저/보조 n-gram 검색을 평가하고, 인덱스 크기 증가도 함께 측정한다. 의미 검색은 첫 버전 필수 의존성이 아닌 교체 가능한 인덱스로 둔다.

## 3D Synapse View: 실제 사건을 공간에 투영

노드는 파일 버전·기억·작업·도구·검증 결과다. 연결은 참조·의존·선택·실행·검증 관계다. 위치는 프로젝트/관련성에 따른 배치이며, 거리나 밝기를 진실성·모델의 실제 attention 값으로 해석하지 않도록 한다.

관측 가능한 사건만 애니메이션으로 표현한다.

| 실제 사건 | 3D 표현 | 기본 한국어 설명 |
|---|---|---|
| 검색 후보 발견 | 후보 집합 표시 | 관련 기록 12개를 찾았습니다. |
| 근거 선택/제외 | 선택 경로 강조, 제외는 흐리게 | 현재 코드와 일치하는 근거 4개를 선택했습니다. |
| 파일 읽기/도구 호출 | 해당 노드로 진행 신호 | 인증 모듈을 읽고 있습니다. |
| 변경안 생성 | 변경 파일 집합 강조 | 두 파일의 수정안을 만들었습니다. |
| 테스트 종료 | 성공/실패 결과 노드 | 8개 통과, 1개 실패. 오류 로그를 확인하세요. |
| 맥락 전달 | GPT/Claude 실행 노드 사이 인계 표시 | Claude에 목표와 검증 근거를 전달했습니다. |

이 문구의 숫자는 이벤트에서 계산하며 예시는 더미 시연 데이터와 구분한다. LLM의 비공개 사고 과정이나 실제 신경망 활동을 본다고 표시하지 않는다. 모델이 만든 설명은 “AI 요약”, 도구가 관측한 사실은 “실행 기록”으로 구분한다. 근거가 없는 설명을 진행 상태처럼 생성하지 않는다.

공식 어댑터가 제공하지 않는 내부 단계는 “관측되지 않음”으로 남긴다. 특히 Claude의 터미널 화면만 있을 때는 정확한 읽기/수정 순서를 추정하지 않는다. 공식적으로 지원되는 구조화 이벤트/후크가 확인되는 범위에서만 세부 시각화를 켠다. 단순 화면 캡처나 ANSI 파싱을 진실의 원천으로 사용하지 않는다.

UI는 3D 지도 + 한국어 진행 타임라인 + 선택한 근거/코드 패널로 구성한다. 시간축으로 재생하고 각 사건을 원본 로그·파일·검증 결과까지 추적한다. 2D/텍스트 모드는 항상 제공한다.

## 3D가 작업 성능을 해치지 않도록

- 전체 DB를 GPU로 올리지 않고 현재 작업의 제한된 부분 그래프만 표시한다.
- 초기 표시 예산 제안: 일반 노드 300개, 집계 노드로 확장. 이는 측정 전 예산이며 성능 보장이 아니다.
- Instanced rendering, 라벨 수 제한, 거리별 상세도, 작업자 기반 레이아웃을 적용한다.
- 사건 수신은 순번과 backpressure를 사용한다. UI가 늦으면 중간 애니메이션 프레임만 생략하고, 영구 실행 기록은 생략하지 않는다.
- 변화가 없을 때 렌더 루프를 멈춘다. 화면 비활성/배터리 절약 시 낮은 FPS 또는 텍스트 모드.
- 창 크기·DPI·렌더 버퍼 크기를 별도 관리한다. WebView/GPU 미지원 시 텍스트 모드로 작업을 계속할 수 있어야 한다.
- 프로세스 전체 메모리와 GPU 메모리를 별도로 기록한다. 앱 프로세스 하나의 RSS만 비교해 절감률을 주장하지 않는다.

## Windows와 macOS

macOS는 .app/.dmg, Windows는 설치형 .exe(NSIS 우선)를 목표로 한다. Windows x64와 macOS Apple Silicon을 우선 검증하고 Intel Mac/Windows ARM은 별도 검증 전 지원 완료로 표시하지 않는다.

Rust core는 경로 정규화, 대소문자, CRLF, 유니코드 경로, Windows junction/reparse point, 장경로, 잠긴 파일의 rename 실패를 테스트한다. PTY는 Windows ConPTY와 Unix PTY를 각각 사용하고 Windows 프로세스 트리 종료는 POSIX 음수 PID와 분리한다.

공식 CLI는 플랫폼별 실행 파일/설치 위치/버전을 확인한다. 재배포 가능한 Codex 아티팩트만 라이선스·해시·버전을 고정하고, Claude는 공식 설치/로그인 흐름을 연결한다. 설치 패키지에 모든 OS용 npm 의존성을 넣지 않는다. 토큰 자동 순환이나 유료 API fallback은 추가하지 않는다.

서명/공증용 Apple Developer ID, Windows 인증서의 사용 가능 여부는 아직 확인하지 않았다. 빌드 성공, CI 실행, 실제 설치·로그인·PTY 동작, OS 보안 경고 없이 배포 가능 여부는 별도 검증 항목이다. 사용자의 인증서를 임의로 찾거나 계약/유료 서비스를 승인하지 않는다.

## 마이그레이션과 복구

1. 기존 앱 작업 종료 및 SQLite 일관된 백업.
2. 새 저장소에 records/summaries를 읽어 content objects·entity·event·manifest로 변환.
3. 레코드 수, 원문 해시, 관계, 실행 상태, 사본 복원 결과를 검증.
4. 새 앱에서 읽기 테스트 후 전환. 기존 DB는 그대로 보존.
5. 실패하면 기존 0.2.x 앱으로 복귀 가능. 원본 DB를 제자리에서 파괴적으로 변환하지 않는다.

추가로 프로세스 강제 종료, 전원 손실 가정, 디스크 부족, DB 잠금, 누락 객체, 중단된 인덱스 생성, 깨진 CLI 설치를 fault injection으로 검증한다.

## 구현 순서와 실제 완료 조건

A. 데스크톱 수직 기능: 앱 창 → 프로젝트 선택 → 편집/저장 → 공식 계정 연결 → 작업 취소/복구. Mac 실물 실행과 Windows CI 설치/실행을 각각 증명한다.

B. 메모리 저장소: 내용 주소 객체 + 정규화된 SQLite + 기존 데이터 import + 검색 + 원본 근거. 동일 작업 100회에서 데이터 증가량을 기존 구조와 비교하고 복원 정확성을 검증한다.

C. 관측 이벤트: 파일 읽기·검색 선택·실행·변경·테스트를 동일 사건 형식으로 수집하고 한국어 타임라인에서 재생한다. 프로바이더별 관측 범위와 누락을 표시한다.

D. Synapse View: C의 같은 이벤트로만 3D를 그린다. 텍스트와 3D의 사건 수·결과가 일치하고 끈 상태에서도 작업이 동일하게 진행된다.

E. 배포: CI에서 플랫폼별 패키지 생성, 버전/아키텍처/해시 표시. Mac 실제 설치와 Windows 실제 실행 근거를 확보하고 공개 베타 릴리스. 서명 여부는 명시한다.

각 단계는 실행 가능한 버전을 유지한다. 첫 데스크톱 버전의 필수 범위는 A+B+C이며 3D는 같은 이벤트 위에 단계적으로 추가한다. 사용자의 최종 요청 범위에는 D와 Windows/macOS 패키지 모두 포함되며 선택 기능이라는 이유로 완료에서 제외하지 않는다.

## 성능 수락 기준 제안

측정 대상은 최소 10개 프로젝트, 1만 지식, 10만 사건의 합성 fixture와 실제 저장소 2개. 동일 기기·동일 모델·동일 데이터에서 비교한다.

- 앱 시작부터 조작 가능까지 p50/p95, 3D 켬/끔의 입력 지연, 유휴 CPU, 전체 프로세스/그래픽 메모리.
- 검색 p50/p95와 정답 근거 회수율. 빨라도 근거를 누락하면 실패.
- 저장량: 최초 데이터, 100회 재실행, 10% 변경, 압축 후, 캐시 제거 후, 복원 시 임시 최대 공간.
- 임베딩·요약·번역의 토큰과 지연을 별도 집계. 보관 압축률을 모델 토큰 절감률과 혼동하지 않는다.
- 목표 예산: 로컬 검색 p95 150ms 이내, 작업 중 UI 긴 멈춤 방지, 3D 활성 30fps 이상을 시작점으로 한다. 기기와 데이터 조건을 명시하고 미달 시 병목을 공개한다. 수치 달성은 구현 후 검증 대상이다.
- 필수 무결성: 저장된 원본의 해시 일치, 미적용 변경 복원, 공유 취소 전파, 삭제/GC 후 참조 무결성, Windows/Mac 취소 후 고아 프로세스 없음.
