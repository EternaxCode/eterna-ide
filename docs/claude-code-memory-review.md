# Claude Code에서 참고한 메모리·개발 흐름 개선

2026-10-18. 공식 문서와 설치된 Claude Code 2.1.215의 CLI 도움말을 분석했다. 비공개 데스크톱 내부 구현을 역분석했다는 의미는 아니다. 사용자 인증·개인 대화·공급사 메모리 파일은 읽거나 복사하지 않는다.

## 근거

- https://code.claude.com/docs/en/memory : 프로젝트 지침과 학습 기억 구분, 짧은 시작 맥락과 필요할 때 상세 자료 읽기.
- https://code.claude.com/docs/en/best-practices : 탐색·계획·구현·검증, 명시적 완료 조건과 실행 가능한 검증.
- https://code.claude.com/docs/en/how-claude-code-works : 오래된 출력 정리와 압축, 장기 규칙을 대화 밖에 보존.

문서는 설치된 CLI보다 새로운 기능을 설명할 수 있다. Eterna는 특정 미지원 Claude 기능을 가정하지 않고 공통 작업 자료를 직접 구성한다.

## 확인한 빈틈

1. 메모리 12개와 이전 답변 3개에 본문 전체가 들어가 전체 프롬프트의 상한이 없었다.
2. 공식 CLI의 규칙 자동 로딩을 끈 실행 방식에서 AGENTS.md/CLAUDE.md가 공통 맥락에 전달되지 않았다.
3. 완료 조건·중단 작업 인계를 명시적으로 구성하는 UI가 없었다.
4. 네이티브 상태 조회가 바뀌지 않은 큰 본문을 반복 전송하고 실행 출력이 없어도 DB를 갱신했다.

## 구현 계획과 수락 조건

- 전체 공통 프롬프트는 UTF-8 64KiB로 제한한다. 토큰 수를 정확하게 안다고 주장하지 않는다. 원문은 보존하고 생략·잘린 자료 수를 표시한다.
- 중요 기억 고정은 검색 우선순위이며 검증 상태나 공유 권한을 바꾸지 않는다.
- 현재 프로젝트의 루트 및 선택 파일의 상위 디렉터리에 있는 AGENTS.md/CLAUDE.md만 제한된 크기로 읽는다. 홈 지침·`.claude` 개인 설정·`@` 외부 참조는 자동 확장하지 않는다. 원문 해시 변경은 이전 맥락 재사용을 무효화한다.
- 완료 조건을 별도 입력하고 GPT/Claude의 동일 자료에 포함한다. 중단/완료 작업 인계는 사용자가 선택하며 자동으로 재실행하지 않는다. 이전 출력은 근거와 공유 권한이 유효할 때만 제한된 분량으로 전달한다.
- SQLite 상태 revision으로 변경 없는 조회를 건너뛰고, 실제 출력 변경이 있을 때만 실행 상태를 쓴다.
- 한국어·대형 본문·공유 철회·지침 변경·재시작·중단 인계·UI 흐름·기존 데이터 보존을 테스트한다. 후보 기억을 자동으로 verified로 승격하지 않는다.

이는 Claude 내부 메모리 엔진 복제가 아니라 공개 설계 원리를 Eterna의 제공사 공통 저장소에 적용하는 작업이다. 네이티브와 기존 웹 경로에 같은 맥락 예산 및 인계 규칙을 적용한다.
